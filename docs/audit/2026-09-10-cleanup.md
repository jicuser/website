## Supabase live read-only audit

Project: pwhtguaevhlnzytneemp. No database changes made.

- Live database lists 10 migrations; repository contains 3 SQL migration files with different version identifiers. Do not replay these files blindly.
- Live migration authenticated_profile_lookup (20260910183000) defines get_my_profile. Neither production_schema.sql nor checked-in migrations defines it.
- Live get_my_profile is stable SECURITY DEFINER with a fixed public search_path, returns id/display_name/role/is_active, and restricts lookup to p.id = (select auth.uid()). anon and authenticated both have EXECUTE. Anon execution is unnecessarily permitted, but the inspected predicate does not demonstrate anonymous profile disclosure.
- Live profiles read policy uses id = auth.uid() OR public.has_role(...). The inspected public.has_role ACL permits only postgres and service_role. This permission mismatch needs a transactional role-level check; the RPC does not prove direct profile queries work.
- profiles update policy uses private.has_role. The production schema still uses public role helpers. Reconcile function definitions, grants, policies and history before schema deployment.
- Security advisor: anon and authenticated SECURITY DEFINER notices for get_my_profile; leaked-password protection disabled. Authenticated execution may be intentional for the restricted self lookup. Do not remove it without validating login.
- Performance advisor: profiles read re-evaluates auth.uid per row. Seven recently added indexes are marked unused; that alone is insufficient reason to delete them.
