# JIC community experience

This release improves JIC’s modular frontend and account configuration, public text, navigation and interactions. Visual reference: https://uselabbaik.com and its public feature pages. The implementation uses JIC branding, original components and the existing service workflows.

Retain React/Vite, Hostinger and Supabase. Use warm ivory, deep green, JIC gold, editorial serif headings, accessible body text, generous spacing and focused service sections. Create original JIC interfaces and use JIC's own assets. Public pages serve visitors to a real centre; they must not sell a software subscription or claim unimplemented payroll, automatic attendance, video recording or payment automation.

The homepage should answer: what happens here, when can I pray, how do I learn or request help, and where do I manage my account? Preserve live prayer data, CMS overrides, announcements, posters, event filtering, radio and donation links. Add an interactive service finder using real destinations, a clearly explained portal section and concise visitor FAQs. Keep mobile touch targets, keyboard operation, reduced motion and dark mode.

Services become a reusable feature module with a central catalogue, intent filtering/search and appropriate empty states. The homepage uses the same catalogue rather than defining another copy. Hidden CMS destinations remain hidden. No demo records are presented as real activity.

Centralise validated authentication return origins and preserve the existing local destination allowlist. Add incremental TypeScript checks and generated Supabase schema types without converting the entire app. Provider/email readiness is read-only; hosted OAuth/SMTP settings are not silently changed.

Review all public source copy for vague promises, internal implementation language and unsupported factual claims. Preserve verified address/contact data, religious text, historical facts, accessibility labels, CMS ownership and existing operational workflows. Record the audit and remaining hosted-content dependencies.

Verify with the existing unit tests/build/lint, meaningful finder and redirect tests, and browser checks at phone/desktop widths in both themes. Deliver on a feature branch with reviewable screenshots and a clear record of any hosted configuration still required.
