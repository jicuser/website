# Code review — November 2026

A short review of structure, security and maintainability, with the Arabic
playground looked at in more detail. Items marked **Done** are in this branch.

## Done in this branch

- **Removed dead Arabic code.** `ArabicWordMap.jsx`, `arabicWordMapModel.mjs`,
  `arabic-word-map.css` and their test were not rendered anywhere (about 700 lines).
- **Arabic CSS loads only on the Arabic page.** `arabic-playground.css` (1,400 lines)
  moved from `src/styles/` into `src/features/arabic/` and is imported by
  `ArabicPlayground.jsx`. The stylesheet every visitor downloads fell from
  250 KB to 225 KB (46 KB to 42 KB gzipped).
- **Live host headers.** `public/.htaccess` (Hostinger) now sends
  `Strict-Transport-Security` and a **report-only** Content Security Policy.
  Report-only blocks nothing; it logs violations in the browser console. Once the
  live site shows none, rename the header to `Content-Security-Policy`.
- **`vercel.json` CSP fixed.** It blocked the Qur'an reader (`api.alquran.cloud`),
  Polycam project embeds and the About page social feeds. Those hosts are added.
- **Planning notes moved.** `docs/superpowers/` is now `docs/history/superpowers/`.

## Recommended next

### Security

1. Enforce the CSP on Hostinger after a week of clean console logs (see above).
2. The About page social embeds run third-party scripts inside sandboxed
   `srcDoc` iframes. That is reasonable; keep `allow-same-origin` out of the
   sandbox list.
3. `npm audit --omit=dev` reports 0 vulnerabilities. Run it before each release.
4. Supabase Row Level Security is the real protection for data. Any new table
   needs a policy and a test in `tests/` before it ships.

### Keeping the site running without help

1. `npm run build` contacts Supabase to make page previews. If Supabase is down,
   the build stops. Build with `JIC_PUBLIC_PREVIEWS=off` to skip that step
   (see README, "If something is down").
2. The public site falls back to content in `src/content/` when the database is
   unreachable. Keep prayer times, address and phone numbers there up to date.
3. `docs/` has about 60 files, many of them dated work logs. Day-to-day you only
   need `README.md`, `CODEBASE_MAP.md`, `docs/editing.md` and `DEPLOYMENT.md`.
   Move the dated `docs/2026-*.md` files into `docs/history/` when convenient.
4. 27 files fail `npm run format:check`. Run `npm run format` once in its own
   commit so later diffs stay small.

### Arabic playground

The data files (`vocabulary.mjs`, `grammar.mjs`, `sentences.mjs`,
`learningContent.mjs`) are plain JavaScript lists. Adding a word or a practice
question means editing those files only, and the tests check them. That part is
in good shape.

The UI is the weak point. Five rewrites in a row (#47 to #51) have left 12
components and 5 stylesheets (about 3,500 lines of CSS) for three tabs. Suggested
order, smallest first:

1. **Merge the stylesheets.** `arabic-playground.css`, `arabic-studio.css`,
   `arabic-structure-explorer.css`, `arabic-connections.css` and
   `sentence-builder.css` overlap. One file per tab is easier to follow.
2. **Pick one sentence view.** The "A sentence" tab shows the structure explorer,
   a change story, an explanation, a colour legend, a "try it" card and a
   collapsed second builder (`SentenceBuilder`). Keep the explorer and the
   explanation; move the rest behind "More".
3. **Arabic font.** `--arabic-font` names Noto Naskh Arabic but it is not
   bundled, so Windows and Android fall back to other fonts. Self-host one
   subset of Noto Naskh Arabic in `public/fonts/` for consistent vowel marks.
4. **Listen button.** It depends on a device Arabic voice, which many phones do
   not have. Short recorded audio for the 80 nouns would be more reliable.
5. **Progress.** Practice rounds are not linked to the words studied. Showing
   practice questions for the words a visitor just opened would make the tabs
   feel connected.

Stop adding new views until 1 and 2 are done.
