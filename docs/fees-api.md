# Shared fee and payment ledger

Status: implementation in progress; additive staging migration required. This records charges and confirmed receipts; it does not collect money or change existing donation providers.

`fee_requests` columns `id,form_id nullable,student_id nullable,course_id nullable,title,amount_minor integer,currency uppercase3-letter,due_at nullable,created_by,created_at,voided_at nullable,void_reason`. Exactly one source: an existing form submission OR enrolled course/student pair. Minor units are pence for GBP (e.g.1250=£12.50). Positive1–100000000. Amount and currency are immutable after creation.

`fee_receipts` columns `id,fee_id,amount_minor integer,method manual|stripe|reversal,reference,note,recorded_by nullable,created_at,reversal_of nullable`. Receipts are immutable. Manual confirmation is a staff statement, explicitly separate from a verified Stripe event. Reversals append a negative receipt matching an existing receipt; they do not send refunds or move money.

- `create_fee_request(p_title text,p_amount_minor integer,p_currency text default 'GBP',p_form_id uuid default null,p_student_id uuid default null,p_course_id uuid default null,p_due_at timestamptz default null,p_idempotency_key uuid default null)` → UUID. Non-null client UUID required; retain across unchanged retries. Source staff permission required. Form staff permission = custom current form membership/manager/globalcustom, or existing legacy kind permission. Learning staff permission = teaches(course) and enrolled student.
- `list_fee_requests(p_form_id uuid default null,p_student_id uuid default null,p_course_id uuid default null,p_outstanding_only boolean default false,p_offset integer default0,p_limit integer default50,p_fee_id uuid default null)` → JSON `{rows:[fee requests plus paid_minor,outstanding_minor,status(unpaid|partial|paid|void)],total,outstanding_minor,outstanding_by_currency:{GBP:1234}}` under RLS. Limit1–100; offset0–25000. Summary uses same source filters, before outstanding-only filter.
- `confirm_fee_payment(p_fee_id uuid,p_amount_minor integer,p_reference text,p_note text default '',p_idempotency_key uuid default null)` → UUID receipt. Staff only. Exact integer minor units, cannot exceed outstanding. Reference required1–160. Non-null client UUID required for retry safety; same key+amount/reference returns receipt, altered reuse rejects. Records method manual; no false provider verification.
- `reverse_fee_receipt(p_receipt_id uuid,p_reason text)` → UUID reversal, staff only; reason required. Only a positive manual receipt can be reversed here; Stripe adjustments require provider reconciliation. Repeated reversal returns existing reversal.
- `void_fee_request(p_fee_id uuid,p_reason text)` → void; staff only and only when net paid is zero. Reason required; immutable audit event records who/when/why. Voiding does not refund money.
- Read `fee_receipts` filtered fee_id for a receipt timeline. Read `fee_audit` filtered fee_id for staff-only audit trail. Both use RLS; no direct insert/update/delete clients.

Form submitters and enrolled student's linked parent/student can read their own fee request and receipts; they cannot confirm money, create charges, reverse receipts or read staff audit. Legacy anonymous form visitors need staff contact; email knowledge alone grants no account access.

Optional `payment-webhook` verifies Stripe's raw-body signature using `STRIPE_WEBHOOK_SECRET` before calling service-only `record_stripe_fee_payment`. It accepts only `payment_intent.succeeded` with metadata `fee_request_id` (server-set on the payment intent), exact fee amount/currency, succeeded status, and unambiguous unique event/payment IDs. No card or customer details are stored. Duplicate events/payment IDs do not duplicate receipts. Payment-intent creation/payment buttons remain outside this ledger; configure an authenticated server payment flow to set metadata safely before enabling this endpoint.

Use `outstanding_by_currency` for totals; never add balances in different currencies. Fee request/receipt writes queue generic `fee` inbox notifications for the linked authenticated submitter or parent/student. `entity_id` is fee ID; access is rechecked when reading or pushing. No private financial data appears on the lock screen.
