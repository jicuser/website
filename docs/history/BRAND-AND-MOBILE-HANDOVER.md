## Known issues and follow-up

1. **Browser/mobile verification is blocked.** The controlled browser could not reach the preview. Do not treat this build as iPhone, Android, accessibility or responsive visual sign-off. Test 320/375/390/430px, tablet and desktop, light/dark and glass/solid. Check menu focus/scroll, native swipes, loaded posters, radio playback, the real invitation, and wallpaper Save Image/Save to Files on physical devices. The wallpaper's two-step share flow follows [MDN's Navigator.share guidance](https://developer.mozilla.org/en-US/docs/Web/API/Navigator/share).
2. **Backend features need further setup.** Only `manage-user` was listed among deployed Edge Functions; `send-contact-email` is absent. The contact form therefore still needs its actual mail backend configured, despite the new email-app fallback. The existing Madrassah enrolment form targets `madrassah_inquiries`, which is also absent from the live database. These are configuration gaps, not successful/verified submission flows. Do not show a success state until an actual submission succeeds. I’tikaf flows and staff invitations have not been end-to-end verified. Do not invent a personal-data table, public insert policy, mail provider or registration endpoint to bypass this work.
3. **Supabase advisories remain.** Leaked-password protection is disabled. `get_my_profile` has security-definer execution warnings: its inspected definition restricts results to `auth.uid()`, so authenticated execution must not be removed blindly. Review anonymous execution and configure password protection through the project's approved settings/migration workflow. A profile read policy also has an auth-initplan performance warning. No permission policies or indexes were changed during this UI task.
4. **Existing dependency advisories remain.** The production-only npm audit reports two moderate package entries (`react-router` / `react-router-dom`). The full audit reports three moderate and one high package entry, including development tooling (`vite` / `esbuild`). Audit-proposed fixes require major upgrades. Keep the development server private, plan upgrades with browser/auth regression tests, and do not use `npm audit fix --force` blindly. This site uses a client BrowserRouter, not SSR; that limits the relevance of the SSR-specific advisory but does not remove the link-handling warning. New CMS notice links reject backslashes and protocol-relative targets.
5. **Repository/deployment status are separate.** The connected repository is public. This task does not change its visibility. Runtime configuration is excluded from Git; no service-role credential belongs in `VITE_*`, assets or frontend code. Preserve Hostinger's existing build-time settings. A source push is not proof that Hostinger has deployed it. Confirm the deployed build separately.

Authenticated admin testing remains deferred per the earlier handover. No staff accounts, messages, enrolments, invitations, database records or password settings were changed during this inspection.
